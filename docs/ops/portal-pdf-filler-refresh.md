## Binding implementation contract

### Context and page identity

- Resolve values against the active, authorized case. Preserve the case's valid selected secondary facility; do not silently fall back to the provider's primary facility. A context change invalidates readiness and results.
- A sequence label such as “Page 3” is presentation only. An untrained heading, by itself, is not step identity. A step is known only from trained, stable evidence that distinguishes it from repeated headings and other frames, after the page settles. Recheck identity immediately before a write.
- A selector miss is drift evidence only for a positively identified step in an accessible frame after the search completes. Hidden, off-step, delayed, inaccessible, or unknown targets do not count as drift. Reconcile results by map/target identity, never label alone.

### Writes, readback, and telemetry

- A setter or PDF writer call is an attempt. Report `verified` only after semantic readback confirms the settled DOM value/selection or the value in the saved PDF bytes. Otherwise report a bounded failure or `unverified`; a fill plan, count, or successful save alone is not verification.
- Expected and actual values may exist transiently in process memory for comparison. **Persisted fill telemetry contains no expected/actual values, raw values, or value-bearing free-text errors.** Store identifiers, counts, and bounded outcome/reason codes only.
- V1 events (including historical events without `schemaVersion` or per-field `kind`) remain readable with their existing historical interpretation. V2 is explicitly marked `schemaVersion: 2` and carries metadata-only per-map outcomes, including positive verified outcomes. Unknown versions fail closed; no new outcome may be treated as success or selector drift by an old reader.
- V2 counters are derived from the per-map outcomes, not from the fill plan. A “last working” timestamp for V2 requires explicit verified evidence for that map. Missing evidence is not success.
- File generation, outcome recording, and a human's payer submission are separate events. Recording may be retried idempotently without generating another file. The extension never submits, signs, uploads, or navigates through payer steps automatically.

The [`fill-event-v2.schema.json`](./portal-pdf-filler-refresh/fill-event-v2.schema.json) file is an **incomplete, non-normative R0 stub**, not a pinned implementation contract. Do not implement it until R1 finalizes attempt semantics, stable map/target/frame identity, qualified `not_found` evidence, counter reconciliation, and the producer/reader compatibility path across every API, browser, and shared-test writer.

### Value and PDF compatibility

- Formats are pure, versioned, and shared by preview, portal, and PDF execution. Unknown required transforms block the field. Native dates use ISO values; trained text/PDF dates use the field's explicit display format without timezone conversion. Invalid or mask-reverted dates remain unresolved.
- Preserve identifier digits and leading zeros. Require approved formatting and exact/unique option matches. Unknown booleans stay unknown; ambiguous choices and credential-degree differences require review. Fixed literals follow the same explicit transform policy as token values.
- Keep the two existing PDF paths compatible while converging their outcomes. AcroForm text, checkbox, radio, dropdown, and option-list controls are supported only where readback succeeds. Flat PDFs are manual completion. XFA is detected and routed to a stated compatibility limit. Signed/certified/encrypted files are preserved and not modified as routine fill input. No OCR, coordinate-template fill, auto-sign, or flattening is implied.

## Deferred decisions and release gates

R0 fixtures are not live payer evidence. Before a live pilot, identify the installed extension build and form version, capture sanitized operator-approved evidence, run the complete applicable local/CI checks, and verify the installed runtime with a credentialing specialist. No source test, fixture, CI result, or generated PDF alone establishes payer acceptance or authorizes release.
