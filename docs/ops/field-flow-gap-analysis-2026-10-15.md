# Field-flow gap analysis — panel UI ↔ form filler ↔ CSV uploads (2026-10-15)

Built from `origin/main` at panel `8b8a59aa` and extension `9e328c1`. Every claim was read from
those commits, not from a working tree. The token inventory in §2 was generated by reconstructing
the `get_sop_field_tokens()` sweep from `src/integrations/supabase/types.ts` (the same method
`src/lib/quickCardCatalog.test.ts` uses) and joining it to the profile projections, the code-owned
token lists, the manual-form inventories and the CSV descriptors.

**Why this exists.** Two symptoms (facility hours never fill; a facility phone is blank while the
group's billing phone exists) turned out to be consistency gaps between three paths that write and
read the same tables: the manual forms, the per-section CSV uploads, and the fill resolver that
serves the Chrome extension and the payer-PDF fill. This document is the map of every mappable
field across those three paths, the gaps, and the fix each gap maps to. Fixes ship as three small
PRs (§5); nothing here adds capability except the PM-approved per-day hours tokens.

## 1. How a field becomes a token

- **The catalog is schema-derived, not curated.** `get_sop_field_tokens()`
  (`supabase/migrations/20260704210000_baseline_live_schema.sql:619`) reads
  `information_schema.columns` over nine tables and emits one `family.camelCaseColumn` token per
  column, dropping only `id, org_id, created_at, updated_at, group_id, facility_id, provider_id,
payer_id, mso_id, status, is_active, is_new_grad, contracting_status_id`. **So every token in
  §2 marked "1-to-1" is a raw column copy by construction**; a new column becomes a token with no
  human in the loop (the quick-card drift test is what catches that).
- **Code-owned families are appended** by `src/services/tokenCatalog.ts`: `user.*` (the caller's
  `profiles` row; `src/server/userTokens.ts`), `billingContact.* / credentialingContact.* /
contractingSigner.*` (the org's default role holder in `parties`; `src/lib/orgContactTokens.ts`),
  and the computed composites (`src/lib/entityTokens.ts`, §3).
- **Three pickers share the catalog.** The web-app mapping picker
  (`src/components/templates/TokenPicker.tsx` ← `listTokenCatalog()` minus
  `src/lib/fillTokenReach.ts` withdrawals) is where a captured portal field is tied to a token; the
  extension's quick-card "Edit layout" picker (`src/lib/quickCardCatalog.ts`, served by
  `GET /api/me/view-prefs`; composites are not offered there); and SOP authoring
  (`src/lib/sopAuthoringTokens.ts`). **The extension has no token picker and resolves nothing.**
- **Values come from one place.** `GET /api/providers/:id/profile`
  (`src/services/providerProfile.ts`) returns `tokens[{token, value}]` with the **raw column
  value** (`Json`) plus `unresolved[{token, reason}]`. The extension turns each value into text with
  `String(raw)` (`minted-extension/src/background/fill.ts`) and applies the field map's `transform`
  (date / phone / TIN / zip / state shapes). The payer-PDF path (`src/lib/pdfFill.ts`
  `buildProviderTokenValues`) renders through `formatTokenValue` instead: booleans → `Yes`/`No`,
  primitive arrays → `a, b`, objects → omitted.
- **Which row each family reads** (`providerProfile.ts`): `provider.*` the provider;
  `group.*` `?groupId` → the case's group → `providers.group_id`, validated against the provider's
  group assignments; `facility.*` / `assignment.*` the explicit `?facilityId`, else the sole
  assigned facility, else nothing + `meta.needs_facility` (in case mode the case's own location
  set); `license.*` the license for the case state → the ad hoc facility's state → `?state` → the
  only license; `groupInsurance.*` via `pickGroupInsurancePolicy`; `payer.* / mso.* / contract.*`
  always null (case-scoped) and already withdrawn from the mapping pickers.

## 2. Token inventory

210 tokens: 152 schema-derived (1-to-1), 11 composites, 47 code-owned (`user.*` + 3 contact
roles × 14 fields). Of these, 25 are case-scoped and never resolve (withdrawn), 4 are withdrawn dead
provider license mirrors, **8 are offered but never resolve on the web fill** (G3), **5 are jsonb and
fill as `[object Object]`** (G1), and 30 column tokens have **no writer in any UI or upload**
(always blank — listed in §4.4).

Column meanings: _Web fill_ = what the extension receives from the profile endpoint today;
_PDF fill_ = `buildProviderTokenValues`; _Mapping picker_ = offered in the web-app field-map
picker; _Quick card_ = offered on the extension's quick cards; _Manual UI writer_ = the form field
that writes the column; _Upload column_ = the per-section CSV header that writes it.

Every composite is built in `src/lib/entityTokens.ts` and used by both fill surfaces
(`providerProfile.ts` for the web, `pdfFill.ts` for PDF). Parts are trimmed; a composite marked
"all parts" resolves to nothing (with an `unresolved` reason) when any part is blank.

| Token                                               | Formula                                                                                                                 | Requires        |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------- |
| `provider.fullName`                                 | `first_name + " " + last_name`                                                                                          | both            |
| `provider.lastFirst`                                | `last_name + ", " + first_name`                                                                                         | both            |

Middle initial and suffix are never part of a name composite. There is no group address composite
and no provider home-address composite on `main` (an uncommitted branch adds them; not assumed
here).

## 4. Upload vs manual form — write parity

The three uploads are `.csv` only, exact-header match (order-free; an unknown or missing header
rejects the file; only `optionalHeaders` may be absent), header normalisation = trim, lowercase,
spaces → `_`. Groups and facilities commit through **the same services the forms use**
(`createProviderGroup`, `createFacility` in `src/services/orgSettings.ts`); providers commit
through the `commit_import_run` RPC (latest definer
`supabase/migrations/20260919033009_provider_csv_add_provider_parity.sql`) plus a client-side
relationship pass (`src/services/importRuns.ts`). Pipeline: `src/lib/importSections.ts`
descriptors → `scanWith` → `stage_import_rows` → preview (`src/lib/importDedupe.ts`) → commit.
