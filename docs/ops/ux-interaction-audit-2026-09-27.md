The [route ledger](ux-interaction-routes-2026-09-27.tsv) identifies 38 active admin page routes plus one shared app-shell control surface, each with a route status and remaining gates. The [control ledger](ux-interaction-controls-2026-09-27.tsv) gives each inventoried actionable control a location, expected result, observed result, evidence, source pointer, and `TESTED`, `FAILED`, or `BLOCKED` status. `TESTED` means the recorded interaction was exercised, not that the entire page is defect-free. `FAILED` is observed staging behavior. `BLOCKED` names an unsafe/unavailable action, missing fixture, or a source-inventoried control with no recorded staging interaction. Source-only inventory rows explicitly say so; they are not staging observations. A page load alone never completes coverage.

**Control totals:** 639 inventoried; 378 `TESTED`, 23 `FAILED`, 238 `BLOCKED`. No inventoried control lacks a status. Full control execution and exhaustive conditional-branch inventory are **not** claimed: many source-known controls lack a staging interaction, and the contracts matrix, uploads, and template/PDF branches remain gated. Repeated rows for one failure represent different controls or retests, not unique defects.

### F10 hosted schema proof and decision boundary

Read-only staging catalog inspection found neither `tentative_effective_date` nor `specialty` on `public.contracts`. The deployed `listContracts()` projection references both. Executing that projection with `WHERE false` returned SQLSTATE `42703` for `tentative_effective_date`; no organization or contract rows were read. The staging migration ledger does not contain `20260926160000_group_contracts_matrix_fields`. Authenticated SELECT grants and RLS exist for the three matrix tables, so the missing column is a direct blocker independent of row access. This does not prove that every matrix action will work after alignment.

The existing migration adds the columns **and** updates or inserts eight contracting status configurations for every organization. Treat it as a hosted data change: review current status values and migration history, prepare backup and rollback evidence, then seek owner approval for a scoped staging alignment. This audit did not apply it.
