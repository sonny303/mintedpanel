Run the loop — the demo script
Seven clicks, six journeys. This is the walkthrough for business.
1On New tab, pick up Jim Apple · Banner — the duplicate warning fires here, on pickup. (J1, J4)
2Follow Open Banner PNM — the launch handoff, no four dropdowns. (J1)
3Fill this page, then mark the step done from the report — progress is inferred, confirmed in one tap. (J3, J4)
4Copy a value from Details while you're there — the card remembers what you pulled. (J2)
5Tick the rest under Progress, add a reference, Record submission. (J4)
6Switch to proview.caqh.org — fill CAQH from our record and record the attestation. Then pull the one value only CAQH has; the next Banner fill becomes 18 for 18. (J6)
7Switch to somepayer.com — an unknown form arrives pre-matched from other payers; assign the one gap and send the proposal. (J5)
Where each journey touches the app
J1Launch from Case Detail resolves the whole context.
J4Submission lands on the case timeline and pre-fills Case Close IDs.
J5Proposed mappings queue for approval in the Template Editor; repairs feed the drift KPI on Payer Setup.
J6Attestation stamps CAQH last attested date; a pulled gap writes the field with a verified-at stamp.
Honest about what's faked
Copy writes to your real clipboard; everything else is local state. The fill runs and field recognition are simulated results, not real page reads — they show the contract, not the parser. Capture stays propose-then-approve — a proposed row never fills until someone approves it, even though the same person does both (enabler 1).
