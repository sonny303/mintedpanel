## Mission

Implement epic **E4.0 — Payer Pipeline: External State Machine, Tracking IDs
& Structured Resolution** from `docs/redesign/E4.0-payer-pipeline.md`
(frontmatter `reviewed: true`, PM review passed 2026-07-14 — you are cleared
to build). Read the whole epic first; its
`## 5. Technical Considerations & Enablers` section (TE-1 … TE-8) pins the
authoritative schema, RPC, and access-control mechanics — build from the TE
sections, not from the feature prose alone. In particular:

- The state vocabulary is the PM-updated seven-state machine:
  **Not Started → Assigned → Drafting → Submitted → In Review ↔ Action
  Required (RFI) → Closed (Approved / Denied)**, plus OON as an explicit
  non-Approved close. `payer_pipeline_state` defaults to `'not_started'`.
- The tracking ID **reuses the shipped `credential_cases.payer_reference_id`
  column** (TE-3) — do NOT add a new column.
- Transitions go through the atomic SECURITY-INVOKER RPC
  `advance_payer_pipeline` (TE-5): a rejected edge writes NO history row and
  NO partial state change, and returns a named error the UI maps to the
  inline "current state / allowed next states" message.
- Corrections, post-terminal edits, and approval-reversal enrollment clears
  are **admin-only inside the RPC** (TE-6); billing stays read-only.
- The case detail ships the user-visible "Payer pipeline history" timeline
  with last-updated attribution (F4.0.1) — visible to all org roles,
  read-only.
