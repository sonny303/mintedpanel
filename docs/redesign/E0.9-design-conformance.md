# E0.9 — Design System Conformance & Stage 0 Tech-Debt Consolidation

## Purpose and Context

Stage 0 (E0.0–E0.8) is functionally complete and hardened, but production has
visually drifted from the approved design system: the app ships Instrument
Sans, a cool-neutral palette (`#164A2F` primary, `#E5E8E6` border), control
shadows, fully-round status pills, and a 1px focus outline — while the
PM-approved design system (landed in-repo at
[docs/redesign/design-system/](./design-system/README.md)) specifies **Geist**,
warm neutrals (`#1B4D3E` primary, `#E8E5E0` border, `#FDFDFC` app), shadowless
1px-bordered controls, 4px status pills with fixed tint+ink pairs, 6px cards,
and a 2px soft primary focus ring. Notably, AGENTS.md's style rules already
claim `#1B4D3E` / `#E8E5E0` — so this epic is **conformance, not redesign**:
it makes the shipped code render the values the system of record already
prescribes. It is a token + component-style migration executed per the
handoff's phased plan ([design-system/changes.md](./design-system/changes.md),
Repo A) plus the PM-approved **Sidebar IA v2** navigation restructure
([design-system/design-system-reference/Sidebar Nav.dc.html](./design-system/design-system-reference/Sidebar%20Nav.dc.html)).

The second half of the epic **consolidates all Stage 0 tech debt**: every open
TD item recorded in the E0.0–E0.8 Devin sections is dispositioned here — either
resolved in this epic or registered, with owner and rationale, in a durable
in-repo register (F0.9.5) so nothing lives only inside epic prose. This closes
Stage 0's books before any Stage 1 planning.

Decision artifacts implemented: the PM design handoff (2026-07-10, recorded in
`CLARIFICATIONS_NEEDED.md` → design-conformance entry), E0.6's nav supersession
precedent, and the E0.0–E0.8 TD inventories.

## Personas Empowered

- P1 Credentialing Manager (Sowmya Seed) — a calmer, consistent visual system;
  a navigation model that matches how the work is actually organized
  (Workspace / Payers / Reporting Center / org zone).
- P5 Practice Owner / P6 Office Manager — public surfaces (capture form,
  shared report) render in the same conformed system, so the brand reads
  consistently outside the app shell.
- Internal maintainers (agents + humans) — a single design-debt and tech-debt
  register replaces debt scattered across eight epic files.

### F0.9.1 — Token + font conformance (design-system values, Geist)

- **Description:** Replace `src/styles/tokens.css` with the conformed token
  file (`design-system/targets/mintedpanel-tokens.css`): warm neutrals, primary
  `#1B4D3E` / hover `#163F33`, app `#FDFDFC`, border `#E8E5E0`, muted
  `#F5F4F1`, ink `#1F2937/#6B7280/#9CA3AF`, fixed status tint+ink pairs
  (replacing `color-mix`), and the DS border-depth/chip tokens. Swap the UI
  font from Instrument Sans to **Geist** (`@fontsource/geist` imports in
  `src/styles.css`; `--font-sans` updated). Geist Mono and tabular figures on
  numbers/IDs are unchanged.
- **Persona:** All app users; P1 primarily.
- **Benefit hypothesis:** ~90% of visual conformance from two files with zero
  component-logic risk — every downstream `--mp-*` reference keeps resolving
  because no token is renamed.
- **Acceptance criteria:**
  - `src/styles/tokens.css` matches the target file byte-for-byte apart from
    any header comment; no `color-mix()` remains in the token layer.
  - Geist renders as the UI font on every route (app + public); Instrument
    Sans `@font-face` blocks and the unused `/fonts/instrument-sans-*` assets
    are removed.
  - `@fontsource/geist` is the only dependency added; Inter imports removed.
  - Computed primary is `#1B4D3E`, app background `#FDFDFC`, border `#E8E5E0`.
  - Every value matches the design system exactly (high-fidelity rule: no
    rounding or re-interpretation).
- **Test/data scenario(s):** TS-21.

### F0.9.2 — Control conformance (shadows, pills, cards, focus)

- **Description:** Bring interactive controls to the DS contract: remove
  `shadow-*` utilities from buttons, inputs, selects, textareas, switches,
  checkboxes, and badges (floating overlays — dropdown menu, tooltip, toast —
  keep their soft shadows); status pills change from fully-round to **4px**
  radius, borderless, using the fixed tint+ink pairs (both `StatusPill`
  implementations); cards/panels move from 4px to **6px** radius; the global
  focus treatment becomes the **2px soft primary ring**
  (`rgba(27,77,62,.18)`, offset 0).
- **Persona:** All app users; keyboard users specifically benefit from the
  focus change.
- **Benefit hypothesis:** Flat, 1px-bordered controls and rectangular pills
  are the DS's core texture; the soft ring keeps focus visible without the
  harsh 1px outline.
- **Acceptance criteria:**
  - No shadow on any input, button, select, textarea, switch, checkbox,
    badge, or card; `dropdown-menu` / `tooltip` / `sonner` keep theirs.
  - Both `src/components/StatusPill.tsx` (4px, DS tint + darker ink, no
    border) and `src/components/triage/StatusPill.tsx`
    (`--mp-radius-control`) conform; the `statusStyles` map uses the
    `*-tint`/`*-ink` token pairs.
  - `src/components/ui/card.tsx` renders 6px (`--mp-radius-sm`).
  - `*:focus-visible` shows the 2px soft ring on light surfaces; a11y
    contrast/visibility for focus is not regressed (E0.8 F0.8.9 pass holds).
- **Test/data scenario(s):** TS-21, TS-24.

### F0.9.3 — Sidebar IA v2 + org switcher restructure

- **Description:** Rebuild the sidebar per the approved spec
  (`design-system/design-system-reference/Sidebar Nav.dc.html` + the
  NAVIGATION section of the reference readme). IA top-to-bottom: **Workspace**
  (Home; Cases with CountBadge) · **Payers** (Payer Management) · **Reporting
  Center** (standalone) · generous break + divider · **org zone** · user
  footer. Tasks roll up under Cases (never a separate item); SOP folds into
  Payer Management; the reserved Setup/Config group is removed. The org zone
  drops the `Org space` label — the switcher IS the header: a contained tile
  (white/6 fill, white/8 border, 6px radius) with an ORGANIZATION eyebrow and
  the org name; children Account Detail / Facilities / Providers; no org
  selected → dashed-border prompt tile. Switcher menu groups orgs by
  lifecycle (Active / Prospects / Inactive), check on the active org, footer
  = Add organization + View all organizations; search appears at 10+ orgs,
  recents-only at 100+. Active item = `rgba(255,255,255,.10)` fill + 2px mint
  inset bar; nav focus uses a white-alpha ring (the soft green ring is
  invisible on forest). User menu gains Settings above Sign out.
- **Persona:** P1 and every authenticated operator.
- **Benefit hypothesis:** The E0.6 nav mixed reserved placeholders with live
  routes; IA v2 lists only real destinations grouped by the actual work
  domains, and makes the org context a first-class switcher instead of a
  labeled section.
- **Acceptance criteria:**
  - Nav shows exactly: Workspace (Home, Cases + open-case CountBadge),
    Payers (Payer Management), Reporting Center; no Tasks, SOP, Setup/Config,
    or `Org space` label anywhere.
  - Route mapping: Home → landing resolver target (`/` behavior unchanged),
    Cases → `/cases`, Payer Management → `/admin/payers`, Reporting Center →
    `/reporting`, Settings (user menu) → `/admin/settings`, Account Detail →
    `/get-started`; Facilities / Providers remain reserved →
    `/soon?title=…`; Add organization → `/onboarding` (E0.8 entry point
    preserved); View all organizations → `/reporting/portfolio`.
  - Switcher menu is lifecycle-grouped with the active-org check; footer
    actions present; with the 11-org seed universe no search field renders
    (≤10 threshold is honored); **no per-org lifecycle status label is
    rendered** (E0.0 locked decision — group headings only, same mechanism
    as the Portfolio precedent).
  - Active/hover/focus states match the spec (white/10 fill + mint inset
    bar; white/5 hover; `outline: 2px solid rgba(255,255,255,.35)` focus).
  - Org-switch behavior (E0.0 TE-4 `<Outlet key={activeOrgId}>` reset) and
    the zero-org first-run path are unchanged.
- **Test/data scenario(s):** TS-22, TS-24.

```gherkin

  Scenario: Operator switches orgs from the contained switcher tile
    Given P1 Credentialing Manager is signed in with Outer Banks Rehab Group active
```

### F0.9.6 — Route re-homing + redirect coverage (E0.0 TD-2 / E0.6 TD-1 close-out)

  - `/portfolio` still redirects to `/reporting/portfolio` (E0.6 TD-1), and
    an automated test covers it plus the reserved-route `/soon` targets.
  - Every remaining flat route either renders or redirects — an e2e/unit
    sweep asserts no 404/blank for the enumerated legacy set.
  - `TECH-DEBT.md` shows E0.0 TD-2 / E0.6 TD-1 as resolved-with-disposition
