# E6.14 — Enrollment Explorer matrix, evidence drawer and bounded CSV

## Purpose and Context

This is Slice 3 of the [WP1.1 parent contract](./enrollment-explorer-wp1.1-requirements.md): one bounded epic and one build PR.
It makes E6.13 capture and publication reachable for staff and gives authorized
clients a matrix, evidence drawer and direct CSV download. Reporting Center is
the entry point; `/reporting/enrollment-explorer` is the only new report route.

The user approved sequential draft build PRs on 2026-09-25 and confirmed this
report work package on 2026-09-28. The E6.14 candidate was reconciled onto
Panel `main` at `64ac2dd1c3aa224512411a423bb4916f5109c846` after E6.12
and E6.13 merged. Merges, hosted changes, client activation, deployment and
production release remain approval-gated. Source, local tests, CI, hosted
runtime and human acceptance remain separate evidence states.

| Persona                                   | Outcome                                                                                                |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| P1 Credentialing Manager                  | Curates targets, reviews captured scopes and publishes or retracts precise client assertions.          |
| P2 Credentialing Coordinator / Specialist | Resolves incomplete captures and saves drafts while retaining source and application history.          |

## Component & Data Constraints

- Reuse Geist tokens, PageHeader, StatusPill, existing dialogs and table patterns.
  Only `@tanstack/react-virtual` is added; no component framework or BI library.
- Preserve the E6.12 staff/client boundary and all six internal navigation links.
  Restricted report leaves mount before staff shell, search or lead hooks.
- Use E6.13 service-only actor/audience-bound APIs. No client memberships,
  direct private-table browser access, source writes or case-key/history changes.
- Additive migration only. Reuse distinct canonical-source batch validation;
  authorize and join actual scopes before interpreting source validity.
- Verify the exact-code taxonomy crosswalk against the official NUCC catalog.
  No discipline inference from credentials, loose prefixes or new taxonomy table.

## Features

### F6.14.1 — Build one authorized matrix population

- **Description:** Serve one cohort/filter contract for the report, detail and CSV.
- **Persona:** P1, P2, P5.
- **Benefit hypothesis:** Authorized completed enrollments remain visible without
  inventing enrollment for active clinicians or planned products.
- **Acceptance criteria:**
  - Authorize organization, selected audience and groups before URL filters.
  - Default cohort unions active verified non-test non-reference provider-group
    records with valid published non-test scopes, retaining inactive/reference/
    terminated clinicians with visible lifecycle labels. Test providers stay
    excluded from clients even if published. Historical mode is explicit.
  - Derive stable product columns from full authorized filtered group/state
    targets plus matching published products before paging 50 distinct providers
    with a stable keyset tie-breaker. Return all matching records for each page
    clinician; locations never collapse and records are never silently truncated.
  - Filter, access and catalog changes invalidate cursor and column identity.
  - Target column labels may appear for authorized groups/states; target DTOs,
    IDs and intent stay private. Target-only cells say No published enrollment,
    never become pending assertions, and produce no detail or CSV record.
  - Actual group assignment qualifies an active-cohort clinician for empty rows
    in that group's target-derived state sections even without a facility
    assignment. An explicit facility filter requires a matching real assignment
    or scope. Published-only lifecycle rows use their actual scope sections.
    An eligible provider-group cohort remains visible when no targets or scopes
    exist, with an explicit unconfigured-product state and no invented columns.
  - Matrix locations and CSV retain one representative per concrete scope.
    Historical mode may add otherwise-hidden scopes through their latest
    authorized, explicitly labeled historical publication. Full immutable
    revision history remains in the lazy drawer; revisions never inflate
    physical location counts or duplicate the same scope in CSV.
- **Test/data scenario(s):** TS-171, TS-175.

### F6.14.2 — Deliver a restricted, usable report surface

- **Description:** Reach the matrix through Reporting Center with shareable filters.
- **Persona:** P1, P2, P5.
- **Benefit hypothesis:** Clients find their report without mounting staff data
  hooks, while staff retain their established navigation.
- **Acceptance criteria:**
  - One route and registry entry; clients see only Reporting Center and this report.
  - URL filters: org, group, state, facility, product, discipline, status and search.
    Query keys include the selected audience/context revision; cancellation and
    post-body checks suppress stale reads and close stale drawers.
  - Distinguish no organization, no grants, empty cohort, loading, query failure
    and unverified-source states. Missing client cells say No published enrollment.
  - Virtualize matrix rows/columns using TanStack Virtual; mobile uses list then
    drilldown. Keyboard activation, Escape and focus return work in the drawer.
  - Exact-code discipline categories are PT/PTA/OT/OTA/SLP; another recognized
    discipline is Other, and blank/unrecognized codes are Unknown.
- **Test/data scenario(s):** TS-172, TS-175.

### F6.14.3 — Review evidence and complete staff capture

- **Description:** A lazy drawer presents exact scope history and reachable staff actions.
- **Persona:** P1, P2, P5.
- **Benefit hypothesis:** Staff can resolve, review and publish evidence without
  exporting internal source metadata to clients or changing operational cases.
- **Acceptance criteria:**
  - Multiple locations show a count badge and exact-location picker. Detail
    preserves group/product/state/facility identity and precise captured dates.
  - Display cycle/revision history, payer reference, retro tri-state and basis,
    owner, safe blocker, reviewed time, source timeline and publication state.
  - Backend provides an audience-safe history DTO. Client history excludes
    internal source IDs, fingerprints, staff IDs, notes and document storage paths.
    History is completely paginated. A historical matrix selection opens History
    directly, including when current detail is no longer authorized.
  - Staff can curate products/targets, open unresolved sources, draft concrete
    scopes, review existing document versions, publish summary/proof and retract
    publication through tested E6.13 APIs. Specialists draft; admins curate and
    publish/revoke. Controls reflect server authority without replacing it.
  - Corrections append revisions; explicit restart uses the tested cycle transition
    and retains prior history. No automatic operational case writes occur.
  - Stale assurance shows Needs verification and labeled historical status, with
    current verified fields/proof withheld. Retracted records supply no new proof.
- **Test/data scenario(s):** TS-173.

### F6.14.4 — Stream a bounded, authorized CSV snapshot

- **Description:** Download actual matching authorized scope records directly.
- **Persona:** P1, P5.
- **Benefit hypothesis:** Export matches the report's meaning and permissions,
  without durable delivery machinery or partial unauthorized artifacts.
- **Acceptance criteria:**
  - Fixed 28-column parent allowlist and order; same server filters and safe
    detail projection. No synthetic no-record cells, internal notes/hashes/source
    IDs/staff IDs, signed URLs, SSN, DOB or home contact data.
  - Staff CSV includes actual matching draft scopes already visible to staff,
    explicitly labeled draft without published/proof assurance. Clients never
    receive draft rows. The selected audience determines rows; the same safe
    field allowlist applies to both audiences.
  - One database snapshot, strictly capped at 100,000 rows and 25 MiB UTF-8.
    Build the complete CSV before delivery. Either overflow returns 413 with no
    partial CSV bytes; no background work, buckets or reusable artifacts.
  - Perform fresh auth/grant/publication validation immediately before native
    Response streaming. Changed authority or snapshot invalidation denies delivery.
  - Escape formulas, controls and embedded newlines safely; preserve empty values.
    Document import-as-text for leading-zero identifiers; never emit an Excel formula.
  - Local Nitro evidence above 4.5 MB verifies complete length/hash and denial
    behavior. Hosted adapter/runtime/plan limits and full-stream behavior remain
    separate release gates; no forced Transfer-Encoding or header-only bypass.
- **Test/data scenario(s):** TS-174.

### F6.14.5 — Measure the agreed workload honestly

- **Description:** Record performance and integration evidence for the real implementation.
- **Persona:** P1, P5.
- **Benefit hypothesis:** The report remains usable at the intended practice size
  without hiding records to meet a headline performance number.
- **Acceptance criteria:**
  - Exercise 3,000 clinicians × 20 products with multiple locations.
  - Record page bytes, controlled API p95, derivation time and steady-scroll long
    tasks against proposed targets of <1 MiB, ≤500 ms, ≤50 ms and no task >50 ms.
  - Keep the measured workload, counts and environment with results. Report any
    unmet proposed target; do not silently cap or call local evidence hosted proof.
- **Test/data scenario(s):** TS-175.

## Dependencies

E6.12 restricted context, E6.13 catalog/capture/publication and source validation,
existing immutable document versions, Reporting Center registry and current UI tokens.
Use native SQL/HTTP, unit and browser tests for their respective boundaries.

| Surface                       | Tables read                                                                                                                                       | Tables written                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Authority                     | `private.internal_staff`, `memberships`, `client_access`, `client_group_grants`, organizations and auth identity                                  | None; existing E6.12 access operations remain separate.                                                         |
| Cohort and matrix             | Providers, groups, provider-group/facility assignments, facilities, payers, private products, targets, scopes, revisions, publications and events | None; exact eligible group/state sections come from actual assignments or authorized scopes.                    |
| Source assurance              | `credential_cases`, `case_facilities`, `enrollment_facts`, immutable scope source links, existing document-version metadata                       | None; operational cases, history and documents are read-only.                                                   |
| Staff capture and publication | E6.13 catalog, source queue, detail and document metadata                                                                                         | Existing E6.13 transactional RPCs append revisions, sources, publications, events and audit; no new write path. |
| History and CSV               | Authorized scope/revision/publication projections and current grant/source/document validity                                                      | None; no export table, retained object, job or snapshot storage.                                                |

Client report DTOs never receive private target intent or internal source fingerprints.
Both staff and client CSV use the same explicit client-safe 28-column projection.
The URL organization is selected-context state; verified request headers and
server authorization remain authoritative. Provider status, reference-only and
verification state are separate fields, not an invented lifecycle enumeration.

initially compared 120,000 projections against 3,000 providers, removing about
360 million pairs. Refreshing fixture statistics removed that bad join plan;
the remaining query still computes source validity and the full-cohort digest
before returning a 50-provider page. The 11-second database query is a product
performance gap. On 2026-09-28 the PM accepted an explicit PR #455 release
exception for this gap (TD-53) and the observed CI scroll-task variance (TD-54)
in [`TECH-DEBT.md`](../../TECH-DEBT.md). The ≤500 ms API p95 and consistently
≤50 ms scroll targets are **not claimed as met**. The 50-provider page stays
under 1 MiB; full-cohort correctness, access control, cursor freshness, CSV
completeness and the existing browser measurement remain required. Staging must
still establish that the report works end to end; an actual timeout, failed
request or unusable interaction is a separate defect, not covered by this
exception. These local results do not establish hosted migration, deployment,
recovery or production readiness.
