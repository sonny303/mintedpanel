# E5.0 — App-Wide Navigation Restoration & Wayfinding Contract

## Purpose and Context

The PM's payer-setup workflow review (2026-07-18) and the app-wide
route-vs-sidebar audit that followed found that the sidebar reaches exactly
ten targets while the app serves ~40 routed surfaces. Six admin surfaces are
fully orphaned (forms test runner, mapping training deck, template wizard,
`/generation` + run history, payer scorecard), five admin pages have no nav
presence (Import, Statuses, MSO Routing, Audit Log, Settings), the 7-section
onboarding wizard has no nav home, the parties manager ("People Enroll") is
buried and unlinkable, and Fix-it / Client Progress fell out of the nav during
the redesign. Orphaned pages also lack any wayfinding: no breadcrumb, no
entity identification, no sense of progress on multi-step surfaces.

This epic is the **presentation-only opener** of the R6.5 payer-setup
enhancement wave (PM decisions D1–D10 locked 2026-07-18, D10 = this epic
ships first). It restructures the sidebar, converts the payer-admin tab pile
into a real nested route tree, institutes a universal three-layer wayfinding
contract (breadcrumb trail → title + entity chip → workflow step strip), and
resolves every orphan with either a nav home, an in-page anchor, or a
fold-and-redirect. **No service, schema, derivation, or wire-contract changes**
— everything here is routes, navigation chrome, and page headers, which is
what de-risks the five functional epics behind it (E5.1–E5.6).

## Personas Empowered

- **P1 Credentialing Manager** — finds every admin surface from the nav;
  always knows which payer/step a setup screen refers to.
- **P2 Credentialing Coordinator / Specialist** — reaches the training deck,
  test runner, and generation surfaces without memorized URLs; Fix-it returns
  to the workspace nav.
- **P5 Practice Owner** — Client Progress returns to the nav (role-gated).

## Component & Data Constraints

- Built from the current component library — see
  [uiux-component-guide.md](./uiux-component-guide.md) and
  [README.md](./README.md). The breadcrumb is a NEW shared primitive: stock
  shadcn Breadcrumb styled by tokens only, logged in `DESIGN-DEBT.md` in the
  same PR (E0.9 governance).
- This epic explicitly authorizes edits to `src/components/layout/*`
  (Sidebar and page-shell headers) — the protected-files rule is lifted for
  exactly those surfaces, per the shell-change precedent (E0.0/E0.6).
- Example/demo/test data uses scenario orgs and personas from
  [seed-universe.md](./seed-universe.md).
- Route restructures MUST preserve every legacy URL as a redirect (the
  `/portfolio` → `/reporting/portfolio` precedent): no bookmark, deep link,
  or e2e entry URL may dead-end.

## Features

### F5.0.1 — Nested admin route tree + legacy redirects

- **Description:** The payer-admin tab pile (`/admin/payer-admin?tab=…`) and
  the scattered admin flat routes become a real nested tree under
  `/admin/payer-setup/*`: `overview` (renamed from "Setup", D8),
  `payer-catalog`, `sop-templates`, `forms` (+ `forms/$payerId/runner`),
  `generation` (+ `generation/runs`, `generation/runs/$runId`), and
  `payer-settings` (D8). Org-admin pages (`import`, `statuses`,
  `mso-routing`, `audit`, `settings`) keep their paths but join the same
  breadcrumb tree. Every old URL — `?tab=` variants, `/admin/portals`,
  `/portals/$portalKey/train`, `/generation*`, `/admin/payers*`,
  `/admin/sops*`, `/admin/templates*` — becomes a `beforeLoad` redirect to
  its new home, preserving params. Named param-preservation set: `?draftId`
  (template-wizard save-as-draft resume), the match-key trio
  `?payerId/state/groupId` ("Needs SOP" prefill links), and the wizard
  section deep-link `?section=` — each asserted in the redirect e2e.
- **Persona:** P1, P2.
- **Benefit hypothesis:** Breadcrumbs derive from route matches for free;
  each workflow gets a stable, shareable URL; the inner tab bar dissolves
  (supersedes FR-6.7's rename — the tab no longer exists).
- **Acceptance criteria:**
  - All admin surfaces render under the nested tree; no `?tab=` state
    remains for primary navigation.
  - Every legacy URL 30x-equivalently redirects (TanStack `redirect`) with
    the named params preserved; a table of old → new URLs ships in the PR
    body AND is pinned in `legacy-routes.spec.ts`.
  - Existing e2e specs pass with entry-URL updates only — no assertion
    weakening.
- **Test/data scenario(s):** TS-104.

### F5.0.2 — Sidebar restructure: collapsible Admin section

- **Description:** Workspace (Home, My Cases, Cases, Fix-it, Client
  Progress) and the Organization zone (org switcher, Account Detail,
  Onboarding, Facilities, Providers, Launches) stay put for daily work.
  `/payer-directory` — the deliberate NON-admin catalog browse that the
  specialist denial screens point to — stays live and non-admin (D9 spirit);
  the admin-gated Payer Catalog nav entry does not replace it. A
  collapsible **Admin** section (rendered for admins only, collapsed by
  default, auto-expands when the current route is inside it) sits at the
  bottom with two groups: **Payer Setup** (Overview, Payer Catalog, SOP
  Templates, Forms & Portals, Generation, Payer Settings) and
  **Organization Admin** (Data Import, Statuses, MSO Routing, Audit Log,
  Settings). Count chips ride existing derivations only (e.g. Cases count
  pattern) — no new queries.
- **Persona:** P1 (admin section), P2/P5 (workspace/org zones).
- **Benefit hypothesis:** Every admin surface is reachable in one click;
  daily-work nav is not polluted by admin density.
- **Acceptance criteria:**
  - Admin section renders only for `admin` role. **Route-gating matrix
    (deliberate D9 gate change, in scope):** `forms/$payerId/runner` and the
    training deck (`/portals/$portalKey/train` successor) become
    writer-reachable; every other `/admin/payer-setup/*` and
    Organization-Admin leaf stays admin-only. Today's blanket
    `/admin/payer-admin` specialist denial pinned by `admin-payers.spec.ts`
    / `payer-admin-module.spec.ts` is intentionally relaxed for those two
    leaves — updating those specs (plus `sidebar-ia` and `legacy-routes`)
    is in scope, not assertion weakening.
  - Newly role-gated routes need the render-time `useRole()` backstop in
    addition to `beforeLoad` guards (the providers new/edit precedent —
    `beforeLoad` reads an empty store on hard-load).
  - Collapsed by default; auto-expands on admin deep links; state persists
    per the existing sidebar-preference mechanism if one exists, else
    session-local.
  - No layout regression on the mobile/narrow breakpoint.
- **Test/data scenario(s):** TS-104, TS-105.

### F5.0.3 — Universal breadcrumb contract

- **Description:** Every authenticated, chromed page renders a breadcrumb
  trail derived from the route tree (never hand-maintained per page):
  `Admin › Payer Setup › Forms & Portals › {Payer} › Test runner`,
  `Cases › {Case} › {Task}`, `Org › Onboarding › {Section}`. Entity crumbs
  (payer, case, provider) link to their canonical parent surface. Public
  entry points (`/welcome`, `/capture/$token`, `/contact`, `/share/$token`,
  `/ssn-intake/$token`) stay chromeless by design and are excluded.
- **Persona:** All.
- **Benefit hypothesis:** "Where am I" is answered structurally on every
  page; the lone "Back to Payer Setup" buttons retire.
- **Acceptance criteria:**
  - One shared Breadcrumb primitive (stock shadcn, tokens only, logged in
    DESIGN-DEBT.md); crumbs come from route matches + a per-route label/
    entity resolver — no page hand-writes its trail.
  - Every crumb navigates; the current page is a non-link terminal crumb.
  - Entity pages (`/tasks/$id`, `/import/$runId`, `/launches/$id`,
    `/providers/$id`, `/cases/$id`) adopt the contract.
- **Test/data scenario(s):** TS-105.

### F5.0.4 — Entity chip beside the title

- **Description:** Pages scoped to a single entity (payer forms runner,
  training deck, scorecard, payer settings detail) render the full entity
  name as a chip beside the page title — no more guessing which payer's
  form is being tested.
- **Persona:** P1, P2.
- **Benefit hypothesis:** Eliminates the operating-context ambiguity the PM
  hit in testing.
- **Acceptance criteria:**
  - Chip renders the full payer name (not the key); styled as a token-only
    pill (`rounded-full` per the design rules).
  - Present on every entity-scoped admin surface; absent on list surfaces.
- **Test/data scenario(s):** TS-105.

### F5.0.5 — Workflow step strip on multi-step surfaces

- **Description:** Multi-step surfaces only — the forms pipeline (Register
  portal → Capture fields → Train mappings → Dry run → Ready to plug in),
  the template wizard, import review, and generation confirm — render a
  step strip under the title. Steps are LIVE state from the same
  derivations the funnel row already uses (`deriveForm` stages et al.) —
  never a stored wizard flag; clicking a completed step navigates to it.
  Single-purpose pages (Audit Log, Statuses) skip the strip.
- **Persona:** P1, P2.
- **Benefit hypothesis:** "Where in the process am I" is visible without
  reading the funnel table.
- **Acceptance criteria:**
  - Strip state is a render-time derivation; zero new persisted state.
  - The strip component consumes a small stage-model interface (ordered
    steps + current + completed) so E5.4's stream rewrite of
    `deriveNextAction` swaps the producer without touching the strip
    (forward-compat requirement, D10 sequencing).
  - Pre-E5.2 edge: for payers where `deriveForm` returns `not_applicable`
    (no `extension_fill` SOP yet), the strip still renders with step 1
    current and a neutral "no fillable SOP yet" note — E5.2 then changes
    only the producer, never this layout.
  - Blocked steps render the blocker reason inline (see F5.0.8).
- **Test/data scenario(s):** TS-106.

### F5.0.6 — Nav restorations & the Facilities repoint

- **Description:** (a) **Facilities** nav item repoints from the `/soon`
  placeholder to the wizard's facilities section — the exact E1.3 TE-11
  precedent that repointed Providers. (b) **Fix-it** returns to Workspace
  nav with its count chip (writers). (c) **Client Progress** returns,
  role-gated (admin + billing). (d) **Onboarding** gets an org-zone entry
  to the 7-section wizard. (e) **Launches** restores under the org zone
  (PM disposition, J-row: restore).
- **Persona:** P1, P2, P5.
- **Benefit hypothesis:** Whole workflows stop being URL-only.
- **Acceptance criteria:**
  - Facilities routes to the wizard facilities section; `/soon` no longer
    referenced by any nav item.
  - The org zone gains three entries into `/onboarding/wizard` (Onboarding,
    Facilities→section, Providers→section — E1.3 precedent): active-state
    rule is `?section=` match wins (Facilities/Providers highlight on their
    section, Onboarding otherwise), reusing the existing `openSection`
    scroll+focus mechanism.
  - Fix-it count chip reuses the existing queue derivation.
  - Role gating follows existing role checks; no new role machinery.
- **Test/data scenario(s):** TS-104, TS-107.

### F5.0.7 — Findability: onboarding link, People Enroll, inbound leads

- **Description:** (a) The **share-onboarding-link re-issue** (capture
  link), today only inside "Add organization", is also surfaced on Account
  Detail and the wizard header for existing orgs. (b) **People Enroll**
  (parties manager) becomes deep-linkable — a sub-tab or `#people` anchor
  on Account Detail, linked from the org zone. (c) **Inbound leads** triage
  moves from the bottom of one org's Account Detail to a cross-org surface
  (Reporting Center entry with a count badge — it is a cross-org queue),
  with the old placement removed.
- **Persona:** P1.
- **Benefit hypothesis:** Re-sending a link to an existing org no longer
  routes through the create-org screen; the contact workflow is reachable.
- **Acceptance criteria:**
  - All three use existing services/hooks unchanged (capture-link issue
    path, `listOrgParties`, `listInboundLeads`) — relocation only.
  - Leads badge renders only when leads await (existing conditional).
- **Test/data scenario(s):** TS-107.

### F5.0.8 — Empty states name the blocker and the ways out

- **Description:** Orphan-page empty states are rewritten to the audited
  contract: what is blocked, why it matters, and both ways out. Flagship:
  the test-runner dry-run step renders "Designate a test provider to run a
  dry fill" with an explanation that the test provider unblocks dry runs
  for EVERY payer, plus [Open the provider roster] and [Skip for now].
  Copy-only on this epic — the roster-side designation affordance ships
  with E5.2 (forms decoupling), which owns the dry-run flow.
- **Persona:** P1, P2.
- **Benefit hypothesis:** Blocked states convert to next actions instead of
  dead ends.
- **Acceptance criteria:**
  - No placeholder text; each rewritten empty state names the blocker, the
    scope of the fix, and at least one navigation affordance.
- **Test/data scenario(s):** TS-106.

### F5.0.9 — Legacy dispositions: fold-and-redirect

- **Description:** Per the PM's J-row dispositions (launches restored in
  F5.0.6): legacy `/home` retires — its action queues were superseded by
  the landing resolver and `/work`; it redirects to `/work`. Legacy
  `/reports` folds into the Reporting Center (its remaining inbound link —
  the case-header link — repoints) and redirects. `/scope` redirects to the
  wizard; `/outcomes` retires to a redirect (both were reserved-leaf
  placeholders). All per the `/portfolio` redirect precedent.
- **Persona:** All.
- **Benefit hypothesis:** One canonical home per workflow; zero dead ends.
- **Acceptance criteria:**
  - Redirect-only — no queue porting in this epic. Pre-decided disposition
    for the one known `/home`-only surface, "Launches at risk"
    (reference-only filtering): accept temporary loss now; it returns as a
    ranked stream in E5.4's consolidated queue. Any OTHER `/home` queue
    found without an equivalent surface → STOP and flag.
  - No route file is deleted; each becomes a redirect stub with a dated
    comment (precedent: `portfolio.tsx`).
- **Test/data scenario(s):** TS-104.

## 5. Technical Considerations & Enablers — Devin section

- **TE-1** Route tree: `/admin/payer-setup/{overview|payer-catalog|sop-templates|forms|generation|payer-settings}`
  as nested TanStack routes; breadcrumbs derive from route matches + a
  per-route `{label, entity}` resolver; flat entity routes (`/tasks/$id`,
  `/import/$runId`) resolve their parent crumb via existing cached reads
  (task→case), never a new query.
- **TE-2** Redirect table shipped in the PR body AND pinned in
  `legacy-routes.spec.ts` (all old URLs in the redirect set; params
  asserted for `?draftId`, the match-key trio, and `?section=`).
- **TE-3** Route-gating matrix per F5.0.2: nav section admin-only;
  `forms/$payerId/runner` + the training deck writer-reachable (D9);
  everything else under payer-setup and Organization Admin admin-only with
  render-time `useRole()` backstops. Spec updates in scope:
  `admin-payers`, `payer-admin-module`, `sidebar-ia` (TS-76 extension to
  the whole Admin section), `legacy-routes`.
- **TE-4** Stage-model interface:
  `{ steps: {key,label,href}[], currentKey, completedKeys, blockedReason? }`
  produced today from `deriveForm`/funnel dimensions; E5.4 swaps the
  producer. `not_applicable` renders per the F5.0.5 edge rule.
- **TE-5** Breadcrumb primitive: stock shadcn Breadcrumb, token-styled,
  DESIGN-DEBT row; the collapsible sidebar section (Radix Collapsible)
  likewise logged.
- **TE-6** Sidebar state: persist collapse via the existing
  `user_table_prefs`/tablePrefs mechanism under a nav page_key (no new
  table); auto-expand on admin route match wins over the stored preference
  for that render.
- **TE-7** F5.0.7 relocations consume `captureLinks`/`parties`/
  `inboundLeads` services unchanged; the leads Reporting-Center entry
  reuses the existing renders-only-when-leads-await conditional + count.
- **TE-8** Mobile/narrow: the Admin section collapses to the same pattern
  as existing nav groups; no horizontal scroll (e2e viewport check).
- **TE-9** Sidebar count chips (Fix-it) mount via the existing cached hooks
  only (Cases-chip precedent); no new queries, no polling.
