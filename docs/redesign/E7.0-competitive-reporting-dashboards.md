# E7.0 — Competitive Reporting Dashboards (Owner Network Health & Ops Pipeline)

## Purpose and Context

Minted’s Reporting Center already answers several operational questions
(Portfolio, Launches, Denials, Expiring Credentials, Audit, Leads). Competitors
(Medallion, Verifiable, symplr) win owner mindshare with an **enrollment matrix**
and clear throughput/TAT storytelling. This epic adds two flagship reports —
**Owner Network Health** (CEO / BD) and **Ops Pipeline** (ops managers) — that
are competitive on **payer-enrollment depth** while staying strictly inside the
current schema. Definitions are single-sourced through pure libs so Cases,
Groups board, and Reports cannot drift.

Decision artifacts: product lock in agent session 2026-08-07; mockups + metric
dictionary under [`reporting-mockups/`](./reporting-mockups/); prior Reporting
Center work E0.6 / E6.6.

## Personas Empowered

- P5 Practice Owner / BD — Network Health matrix + this-month throughput; shareable.
- P1 Credentialing Manager — Ops Pipeline (Provider Network · Workload · Turnaround).
- P2 Coordinator — workload attribution via touches (not sparse `assigned_to`).

## Component & Data Constraints

- Design system + stock shadcn only; mockups in
  [`reporting-mockups/index.html`](./reporting-mockups/index.html) are IA
  reference, not pixel law. Chart library deferred — tables, KPI cards, and
  simple bar tracks matching existing Reporting Center / Cases patterns are
  sufficient for v1.
- Metric names and grains are closed in
  [`reporting-mockups/METRIC-DICTIONARY.md`](./reporting-mockups/METRIC-DICTIONARY.md).
  **Hard rule: do not invent metrics or statuses not in the dictionary.**
- Data sources: `credential_cases.case_status`, `case_status_history`,
  `enrollment_facts`, `payer_network_targets`, `touches`, `tasks`,
  `state_licenses`, `provider_documents` (via `documents` lib), existing
  pure libs (`caseRollups`, `followUps`, `launchReport`, `providerGaps`,
  `generationBuffer`, `payerIssuedIds`, `nextBestActions`, `denials` /
  `buildDenialRows`).
- **Do not** read `payer_pipeline_state`, `payer_pipeline_history` (writer
  dormant), or `credentialing_status_id` as KPI sources.
- Hosted probe 2026-08-07 (`fkvuhfsqcmujywzgczmc`, org BEST Physical Therapy):
  1 case, 0 facts, 0 touches — **schema OK, volume insufficient**. Build
  acceptance requires seed-universe (or restored backup) fixtures; see
  Scenario/Seed Data Mapping.

## Features

### F7.0.1 — Shared metric layer (anti-drift)

- **Description:** New pure modules under `src/lib/` (e.g. `enrollmentMatrix.ts`,
  `reportingTat.ts`, `networkHealth.ts`) implement dictionary definitions once.
  Owner and Ops surfaces, and any KPI also shown elsewhere, import these
  reducers — no second open-case or Active definition.
- **Persona:** P1/P5 (trust).
- **Benefit hypothesis:** Fixes the disconnection/overlap problem (facts vs
  approved, Cases vs board vs reports).
- **Acceptance criteria:**
  - Active = live fact OR approved (matches `groupPayerFulfillment` semantics
    at the grain each metric declares).
  - Open case set matches `OPEN_CASE_STATUSES` in `caseStatus.ts`.
  - Unit tests cover matrix cell resolve (Active wins over parallel open),
    state collapse, Not Started when in-scope empty, TAT medians from history.
  - Grep/guard test (or documented allowlist) ensures report UI does not
    branch on pipeline/credentialing mirrors.
- **Test/data scenario(s):** TS-141 (unit + seeded org).

### F7.0.2 — Owner Network Health report

- **Description:** Reporting Center entry (Performance group) at
  `/reporting/network-health`. Active-org only. Composition:
  1. This-month (or trailing-window) strip: Approved / Submitted / Denied
     counts + median create→approve days — **history-based**.
  2. **Enrollment matrix** provider × payer with group chips + optional
     state filter; cell rules per metric dictionary (29A/30A/31B).
  Share link (extend `report_shares` / `ShareReportPanel` pattern beyond
  Portfolio) + CSV download.
- **Persona:** P5.
- **Benefit hypothesis:** Owner sees network standing at a glance without
  spreadsheet “PTP” / invented statuses; competitive with enrollment-matrix
  products while honest to Minted’s model.
- **Acceptance criteria:**
  - Only dictionary statuses render (no Gathering docs / PTP).
  - Active cell when live fact OR approved even if another open case exists.
  - In-scope empty cell = Not Started (columns = active-target payers for
    group filter).
  - Share token validates server-side org scope; CSV columns documented.
  - KPI cards for Active %, open cases, at-risk launches, standing denials,
    risk watch are **not** on this page (moved to Ops).
- **Test/data scenario(s):** TS-142 (matrix + share + CSV).

### F7.0.3 — Ops Pipeline report

- **Description:** Reporting Center entry at `/reporting/ops-pipeline` with
  underline tabs (Cases-detail style): **Provider Network → Workload →
  Turnaround**. CSV per tab. No share token in v1.
- **Persona:** P1.
- **Benefit hypothesis:** One ops home for network risk, effort, and speed
  without competing CEO narrative.
- **Acceptance criteria:**
  - Provider Network hosts: Active network %, open cases, at-risk launches,
    standing denials, risk watch, fulfillment bars, provider coverage
    snapshot — all dictionary-defined.
  - Workload uses touches/`followUps`/`tasks`/`buildNextBestActions`;
    coordinator rollup primary key = `touches.coordinator_id` (Unattributed
    bucket). Do not require `assigned_to`.
  - Turnaround medians share the same functions as Owner’s median strip.
  - Tab order matches mockup rev 2.
- **Test/data scenario(s):** TS-143.

### F7.0.4 — Reporting Center registry + legacy /reports retirement

- **Description:** Register both reports in `src/lib/reports.ts` under
  Performance. Redirect `/reports` (and any SummaryTab/RosterTab entry) to
  `/reporting` (or the appropriate new report). Existing reports unchanged.
- **Persona:** P1.
- **Acceptance criteria:**
  - Index lists both NEW reports with accurate descriptions.
  - `legacy-routes` e2e moves `/reports` to redirect set.
  - No second reporting truth remains reachable in the shell.
- **Test/data scenario(s):** TS-23 retarget / TS-144.

### F7.0.5 — Distribution contracts

- **Description:** Owner share uses existing `report_shares` machinery with a
  new report key; validate RPC scope remains server-enforced. CSV via
  `src/lib/csv.ts` following Denials export pattern.
- **Acceptance criteria:**
  - Revoked/expired share lockdown parity with Portfolio share e2e.
  - Ops tabs expose Download CSV only (no Share).
- **Test/data scenario(s):** TS-142 share slice.
