# E6.14 Design Spike Notes — Enrollment Explorer & Proof Engine Drawer (WP 1.1)

**Date:** 2026-09-25  
**Epic:** E6.14 / WP 1.1  
**Target Surface:** `/reporting/enrollment-explorer`  
**Audience:** Internal Staff (`admin`, `specialist`, `billing`) and Verified External Clients (`audience: "client"`)  
**Design Reference System:** Geist Design System, `#0C2A1D` Sidebar Tokens, Minted Panel Primitives (`src/components/ui/*`)

---

## 1. Executive Summary & Mobbin Benchmarking

Before implementing the production components for the **Transparent Enrollment Explorer**, we conducted a targeted design spike evaluating interaction patterns from top-tier SaaS benchmarks indexed in Mobbin (including Attio, Linear, Melio, Ramp, and Stripe Dashboard).

The core challenge of the Enrollment Explorer is **balancing extreme data density with instant auditability**:
- A practice manager or billing specialist needs to scan a 3,000+ clinician $\times$ 20+ payer product matrix to spot gaps, pending actions, and effective dates.
- At the same time, clicking any cell must provide definitive, primary-source proof (SHA-256 byte-verified documents, precise milestone timestamps, action owners, and retro windows) without navigating away from the matrix context.

---

## 2. Benchmark 1: High-Density Data Grids / Multi-Dimensional Matrices

### Benchmarks Referenced:
- **Attio (Table Views):** Compact row density, multi-attribute cell representations, sticky identity columns with subtle horizontal shadows upon scrolling.
- **Linear (Issue Matrix):** Keyboard-navigable cell grids, stark border delineations, subdued empty states (`text-muted-foreground/40`), high-contrast status tokens.

### Locked Architectural Decisions:

| Dimension | Decision | Rationale |
|---|---|---|
| **Cell Padding Tokens** | `py-1.5 px-2` (Compact Density) | Standard table padding (`p-4` or `py-3 px-4`) creates excessive whitespace and forces constant scrolling across 20+ payer products. `py-1.5 px-2` with `text-[12px]` delivers maximum scanability while keeping click targets accessible ($\ge 32\text{px}$ row height). |
| **Sticky Column Hierarchy** | Double-pinned: Sticky Payer/Product headers (`top-0 z-30`) + Sticky Clinician Identity Column (`left-0 z-20`) | Clinician identity (Last Name, First Name, NPI, Discipline) remains locked on the left rail as the user scrolls horizontally through payer products. The header has a two-tier hierarchy: Top tier groups by Payer (`h-8 text-[11px] font-semibold uppercase tracking-wider text-muted-foreground bg-muted/60 text-center`), bottom tier displays Product names (`h-9 text-[12px] font-medium text-foreground bg-muted/30`). |
| **Empty / Uncontracted Cells** | Subtle centered en-dash (`—`) in `text-muted-foreground/40` | Avoids visual clutter from repetitive "None" or "Not Applied" pills. Keeps uncontracted space clean so active statuses, blockers, and approvals pop visually. Hovering indicates "No published enrollment" with subtle highlight `hover:bg-muted/20`. |
| **Cell Status Representation** | Tokenized `StatusPill` with Action Owner dot/badge | Approved cells display Green `StatusPill` with optional effective date. Pending cells display Blue/Yellow `StatusPill` with Action Owner indicator (`Minted`, `Client`, `Payer`). Blocked cells display Amber/Red warning badge. Cells with multiple facility locations show a compact count badge (e.g. `2 locs`). |
| **Truncation & Tooltips** | Strict single-line truncation with full-value native tooltip | Clinician names truncate at `w-[140px]`, product titles truncate at column width (`w-[140px]`), displaying full string on hover to preserve grid geometry. |

## 3. Benchmark 2: Slide-Over Detail Inspector / Proof Drawer (The Proof Engine)

### Benchmarks Referenced:
- **Melio (Payment Detail Drawer):** Step-by-step linear audit timeline showing date progression, party attribution, and payment reference numbers.
- **Ramp (Transaction Detail Drawer):** Attached proof receipts, immutable verification badges, and explicit action-required callouts.

### Locked Architectural Decisions:

| Dimension | Decision | Rationale |
|---|---|---|
| **Drawer Width** | `w-[500px] max-w-[90vw]` (`sm:max-w-lg`) | `max-w-md` (28rem / 448px) causes wrapping of long SHA-256 hashes, file names, and multi-location addresses. `500px` allows comfortable 2-column key-value pairs and clear document cards without obscuring the parent matrix. |
| **Drawer Layout** | Linear Milestone Timeline over Tabbed Views | Benchmarking Melio demonstrates that a single, unified vertical timeline (Intake $\to$ Submitted $\to$ Payer Acknowledged $\to$ Approved $\to$ Effective) is far superior to tabs for operational audit trails. Users see the full chronological story in one scroll without missing critical blockers. |
| **Status Banner & Action Owner** | Prominent Top Header Card: Status badge + Action Owner badge | Placed immediately below the clinician/product title block: Status (`StatusPill`) paired with Owner (`Minted Panel` | `Client / Clinician` | `Payer`). Eliminates ambiguity about whose turn it is to act. |
| **Active Dependency / Blocker Callout** | Dedicated Warning Banner (`var(--mp-warn-tint)` / `var(--mp-warn-ink)`) | If an enrollment is blocked (e.g. "Awaiting clinician signature on CAQH attestation"), it renders in an assertive alert box with explicit next steps and target follow-up date. |
| **Audit Evidence & Proof Documents** | Version-Bound Proof Document Cards with SHA-256 badge | Each approved publication lists attached proof documents (Payer Approval Letter, Roster Confirmation, PSV License) with evidence kind, supported verified fields, and authenticated download link. Displays "SHA-256 Verified" pill. |
| **Tenant Safety Invariant** | Automatic Field Stripping for External Clients | When `audience: "client"`, internal staff notes, internal tracking IDs, unreviewed draft revisions, and internal-only uploads are strictly omitted from the drawer DOM. |

## 4. Benchmark 3: Filter Bar & Compound Search

### Benchmarks Referenced:
- **Attio & Stripe Dashboard:** Horizontal compact filter strips with active count chips, inline debounced search, and clean "Clear all" mechanics.

### Locked Architectural Decisions:

| Dimension | Decision | Rationale |
|---|---|---|
| **Bar Placement** | Persistent Horizontal Filter Bar below KPI Strip | Persistent placement ensures the user always understands current matrix scoping without opening modals. |
| **KPI Summary Strip** | 4-Metric Quick Stat Cards | Positioned directly above the filter bar: <br>1. **Total Clinicians** in current scope.<br>2. **Active Enrollments** (In Network / Approved).<br>3. **Pending Payer Action** (Submitted / Under Review).<br>4. **Actionable Client Blockers** (Awaiting signature / info). |
| **Quick Search** | Inline Search Input with 200ms debounce | Debounced search queries both Clinician Name (`Last, First`) and 10-digit NPI without triggering layout thrashing during keystrokes. Includes clear (`X`) button. |
| **Dropdown Filters** | Organization / Facility, Provider Group, Discipline, Status Bucket | - **Provider Group:** Automatically locked/disabled for external clients with a single granted group; multi-group clients can only pick from their verified `clientOrgs.groups`.<br>- **Discipline:** Filter by NUCC crosswalk (`All`, `PT`, `PTA`, `OT`, `OTA`, `SLP`, `Other`).<br>- **Status Bucket:** Grouped operational statuses (`All`, `In Network / Approved`, `In Progress`, `Action Required / Blocked`). |
| **Filter Badges & Clear All** | Active count chips with "Clear all" button | When filters are active, an active filter count is displayed with a one-click "Clear all" button restoring the default view. |

## 5. Benchmark 4: Client-Facing CSV Export

### Benchmarks Referenced:
- **Linear / Attio CSV Exporters:** Clean tabular export with guaranteed formula sanitization and preserved business identifiers.

### Locked Architectural Decisions:
1. **Fixed Column Sequence:**
   `Provider Name`, `NPI`, `Discipline`, `Group`, `Payer`, `Product`, `State`, `Facility`, `Status`, `Publication State`, `Effective Date`, `Action Owner`, `Blocker Reason`, `Payer Reference #`, `Retro Window`, `Proof Count`.
2. **Formula Injection Sanitization:**
   Any cell starting with `=`, `+`, `-`, or `@` is prepended with a single quote `'` to neutralize formula execution in Microsoft Excel and Google Sheets.
3. **Identifier Integrity:**
   10-digit NPIs and 9-digit TINs are formatted safely to ensure spreadsheet applications do not drop leading zeros.
4. **Role Isolation:**
   External client exports contain exclusively client-safe data and granted provider groups; internal notes, internal staff IDs, and draft revisions are excluded.
