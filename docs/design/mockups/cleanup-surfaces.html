Cleanup surfaces — design package
Design package · July 2026

The cleanup side: find it in the app, fix it in thirty seconds

The extension is where users do tasks; the app is where they find and kick off cleanup. These three connected surfaces turn fill-coverage gaps into small, celebrated decisions — no timers, no speed mechanics, corrections counted as good catches. Mockups reproduce the shipped design system: Instrument Sans, forest-green sidebar, white cards, 1px borders, no shadows. The app canvas is light-only by design.

FIND & KICK OFF cleanup — the three surfaces below

1 · Fix-it queue — 30-second decisions, ordered by impactHome + /fix-it
2 · Mapping review — card-by-card training for a new form/portals/$key/train
3 · Portals admin — the registry: URLs, coverage, verification/admin/portals

Coverage, one number

Per provider × portal: fields that auto-fill / fields mapped. A field auto-fills when its approved map row resolves — a token with a non-null value for that provider, or a hardcoded value. Gaps are what the Fix-it queue hunts.

“46 of 52 fields auto-fill”

Impact order, never ease

The queue sorts by soonest blocked fill first (the blocking case’s next open task due date), tie-broken by fields unlocked. Dictionary and training cards slot in by the earliest fill they affect.

No “quick wins” sort. Ever.

Dictionary & confidence

Label → token memory, org-scoped. A label seen twice with the same mapping earns a confirm card; a confirmed rule makes future suggestions high-confidence, batched into one screen in training.

High = batch · Medium/Low = one card at a time

Celebrate corrections

Saying No to a wrong guess is a good catch — counted and thanked, never penalized. No timers, no streaks, no speed mechanics anywhere on these surfaces.

Locked product principle

Data model — rides the existing lifecycle, two new tables, three additive columns

EXISTING (unchanged) portal_field_maps.status: proposed → approved → retired · source: token | manual | hardcoded fill_sessions (fields_filled per portal fill) · tasks (skip → follow-up task on the blocking case) NEW portals org-scoped registry: portal_key, name, payer_id, form_url, is_verified, last_verified_at, url_changed_at — RLS: member select, writer write (same as payers) NEW field_dictionary org-scoped label → token memory: label_normalized, token, status (suggested | confirmed | rejected), seen_count — unique (org_id, label_normalized) ADD portal_field_maps + field_label text, form_section text, confidence smallint (0–100, proposed rows)
